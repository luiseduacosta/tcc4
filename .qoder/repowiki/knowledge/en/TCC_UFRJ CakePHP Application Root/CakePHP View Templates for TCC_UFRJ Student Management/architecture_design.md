Templates follow CakePHP's conventional layout: each controller has a matching subdirectory under `templates/<Controller>/` (`Estudantes/`, `Monografias/`, `Users/`, `Professores/`, `Tccestudantes/`, `Agendamentotccs/`, `Areamonografias/`) containing standard CRUD action files (`add.php`, `edit.php`, `index.php`, `view.php`). Shared UI is factored into `element/` (reusable fragments like `menu_monografias.php`, `paginator.php`, `templates.php`, and `flash/{default,error,success}.php`) and `layout/` (`default.php` as the main HTML shell with Bootstrap 5.3 + CKEditor 5 + jQuery, plus `ajax.php` and `error.php` for special response types). Email rendering uses paired `email/html/` and `email/text/` default templates wrapped by `layout/email/{html,text}/default.php`. Static pages live in `Pages/` (e.g. `home.php`). Error responses are rendered from `Error/error400.php` and `Error/error500.php`. Dependency direction is one-way: action templates consume elements and layouts via `$this->element()` and `$this->fetch()`, never the reverse; data flows in through CakePHP's `AppView` variables (entities, request attributes like `identity`, and paginator helpers). Global helper template overrides (Form, Paginator, Html, Breadcrumbs) are centralized in `templates/element/templates.php` so every view inherits consistent markup.
