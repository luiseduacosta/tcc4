The suite follows CakePHP's standard `tests/` layout with three layers. `bootstrap.php` loads the app autoloader and config, sets `App.fullBaseUrl`, registers an in-memory SQLite connection named `test_debug_kit` aliased to `debug_kit` for DebugKit, and fixes the session ID to `'cli'`. `Fixture/` contains one `*Fixture.php` per table that extends `Cake\TestSuite\Fixture\TestFixture`, declares the target `$table`, and seeds rows via `init()`. `TestCase/` mirrors the production namespace: `Controller/*ControllerTest.php` classes extend `Cake\TestSuite\TestCase` and use `IntegrationTestTrait` to simulate HTTP requests; `Model/Table/*TableTest.php` classes obtain their subject through `getTableLocator()->get('<Entity>', ['className' => EntityTable::class])`; `View/Helper/` is reserved for helper tests. A top-level `ApplicationTest` asserts plugin registration (Bake, DebugKit, Migrations, CakePdf, Authorization, Authentication) and validates the middleware pipeline order (ErrorHandlerMiddleware → AssetMiddleware → RoutingMiddleware). Dependency direction is one-way: tests depend on the application under test via the `app.*` fixture naming convention and `App\Model\*` namespaces.
